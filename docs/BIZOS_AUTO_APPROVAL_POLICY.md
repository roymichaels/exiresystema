# BizOS Auto-Approval Policy

## Policy Overview

The BizOS Auto-Approval Policy defines the **approval levels** and **decision boundaries** for automated improvement proposals generated by the Continuous Vision Improvement Pipeline.

**Current Status**: **Manual Approval Required** - All improvements require explicit Dean approval before implementation.

This policy establishes a **safety-first framework** for gradual automation of improvement implementation while protecting critical infrastructure and maintaining human oversight.

## Approval Levels

### LEVEL 0 — NEVER AUTO-APPROVE ❌

**Protected Categories** - Changes that can **never** be auto-approved:

#### Infrastructure and Core Systems
- **Supabase schema** - Database structure modifications
- **auth/RLS** - Authentication and Row-Level Security changes
- **Edge Functions** - Serverless function implementations
- **OpenRouter gateway** - External API integrations
- **payments/subscriptions** - Payment processing logic

#### Business Logic Protection
- **Production business logic** - Core business rules and workflows
- **route restructuring** - Application routing architecture changes
- **source folder/package refactors** - Codebase organization modifications
- **broad i18n rewrite** - Large-scale internationalization restructuring

#### Critical Data Systems
- **AION deletion** - AI consciousness system removal or major changes
- **Web3/FM deletion** - Blockchain and financial modeling system changes

**Policy Rationale**:
These systems represent the foundation of the platform and Exire Systema tenant. Any unauthorized changes could compromise data integrity, security, or core business operations. Manual review by Dean ensures proper risk assessment and change management.

---

### LEVEL 1 — HUMAN APPROVAL REQUIRED FOR NOW 👤

**Significant Changes** - Requires manual Dean approval:

#### User Interface and Components
- **UI changes** - User interface modifications and enhancements
- **component refactors** - Component structure and logic changes
- **tenant config implementation** - Tenant-specific configuration updates
- **advisor behavior changes** - AI advisor functionality modifications

#### Business Logic Systems
- **CRM/client/customer logic** - Customer relationship management systems
- **business dashboard changes** - Business analytics and reporting interfaces
- **route changes** - Application routing architecture modifications

**Policy Rationale**:
These changes impact user experience, business operations, and system functionality. Manual approval ensures proper testing, validation, and impact assessment before implementation.

---

### LEVEL 2 — CAN BE AUTO-PROPOSED ONLY 📋

**Documentation and Process Improvements** - Can be auto-proposed but require Dean approval for implementation:

#### Documentation Improvements
- **docs improvements** - Documentation updates and enhancements
- **ticket suggestions** - Automated ticket generation and improvements
- **terminology cleanup suggestions** - Language and terminology standardization
- **roadmap suggestions** - Strategic roadmap updates and refinement

#### Architecture Proposals
- **architecture proposals** - High-level design and structural recommendations

**Policy Rationale**:
These improvements focus on documentation, process, and high-level guidance without direct impact on production systems. They provide actionable recommendations while maintaining human oversight for implementation decisions.

---

### LEVEL 3 — FUTURE AUTO-APPROVE CANDIDATES 🤖

**Automatable Improvements** - Can be auto-approved after Dean validates the pipeline:

**Current Requirements**:
- **Dean validation of pipeline effectiveness**
- **Comprehensive testing and validation**
- **Risk assessment and mitigation strategies**
- **Rollback capability confirmation**

**Planned Auto-Approval Categories**:
- **formatting docs** - Documentation formatting and standardization
- **adding missing checklist sections to tickets** - Automated ticket enhancement
- **generating analysis reports** - Scheduled report generation
- **updating report timestamps** - Automated metadata updates
- **adding non-source docs cross-links** - Internal documentation linking

**Policy Rationale**:
These improvements focus on non-functional, administrative, and quality-of-life changes that can be safely automated once the pipeline demonstrates reliable, safe operation.
